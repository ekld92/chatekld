# ChatEKLD 2026 Project Notes

ChatEKLD is a local macOS app for PDF summarisation and Obsidian vault RAG. It uses Flask, PyWebView, SQLite, LlamaIndex, Ollama, and LM Studio.

> **Layered docs.** This file holds the cross-cutting rules and invariants only. Deep implementation notes live in subtree `CLAUDE.md` files that load on demand when you work in those directories: `rag/CLAUDE.md` (indexing pipeline, locks, prewarm, retrieval mechanics), `core/llm/CLAUDE.md` (adapters, fallback policy, usage/pricing, tool wire formats), `core/agent/CLAUDE.md` (agent loop), `audit/CLAUDE.md` (Library Audit internals + endpoint details). History lives in `CHANGELOG.md`. Deferred items are under **Known Issues** at the bottom.

## Current Workflows

- Single Paper. Upload one PDF. Extract text. Stream a tunable summary with prompt presets, document-type prompts, audience, focus question, and generation controls.
- Obsidian Vault. Index `.md` and `.pdf` files. Query the vector index through dense retrieval, optional BM25 lexical retrieval, RRF fusion, and optional cross-encoder reranking; inspect the indexed-material manifest.
- Library Audit. Read-only reconciliation of the Obsidian vault against Zotero (SQLite snapshot + Better BibTeX `_master.bib`), local PDFs (annotations + duplicates) and macOS Finder tags — with exactly one vault-write action, the confirm-gated `apply-tag-drift` (see Library Audit Rules). The reports (incl. the per-paper **Finder Tag Drift** (`finder_tag_drift`, 2026-08-05 — Finder-vs-note tags via the shared fingerprint; only papers carrying ≥1 Finder tag are compared; **correctable since 2026-08-06**: per-row `[→ note]` / `[→ Finder]` verbs dispatch to the TAGGING subsystem's journalled writers (`apply-note-tags` / `apply-finder-tags`) — never a new audit write path — using the payload's per-surface `vocab_ids` mapping (drift surface → exact `_tags.md` id via the audit fingerprint, so the writers' literal-id vocab gate accepts what the report offers); out-of-vocab surfaces are badged not-applyable with a per-tag `[+ vocab]` that chains the journalled `POST /api/tagging/add-vocab-tag` then the apply; rows also carry `variants` (present-both-sides spelling near-misses, informational) and `note_rel`), **"Possible Duplicates"** (`near_duplicates`, 2026-08-05 — evidence-tier candidates for byte-*different* copies of the same paper: normalized first-page text, DOI/arXiv id, multi-PDF keys, title+year±1+author record pairs, plus a rapidfuzz similarity sweep (cutoff `audit_near_dup_ratio`, default 88); per-group dismiss persisted in `dup_decisions.json`, undoable), **"PDFs Without Zotero"** — `read_unzoterod`, the COMPLETE un-Zotero'd set, read and unread, whose meta line discloses the ambiguous / confirmed-no-match / skip-prefix rows it omits — and its filtered subset **"↳ Unread Only"** (`unread_unzoterod`); the two are superset ⊃ subset, **not** a partition, and were mislabelled as one until 2026-07-31, which hid the full list. Also the ambiguous-PDF picker, the skipped-PDF list, and the read-only **Tag Hygiene** view — cross-store tag frequencies grouped by an OpenRefine-style fingerprint, `_tags.md` vocabulary flags, near-miss neighbour clusters and top co-occurrence pairs, computed on demand at GET over the cached inventory; its fingerprint recipe lives in the vendored-tree-local `audit/engine/normalize.py` since 2026-08-05, shared with the drift comparison — `audit/` still depends only on `audit/config.py`) plus a per-citation-key inventory. Engine vendored from kb_harmonizer under `audit/`. Strictly manual — the scan runs only when the user clicks Run Scan.
- Biblio Tagging. A **Library Audit sub-view** (the "Tagging" report tab) that turns the audit's per-citation-key `Record` join into a *write* surface for tags, scoped strictly to `biblio_articles/`. Per paper: **Propose** (an LLM suggests tags from the vault's `_tags.md` vocabulary using the PDF's cached text), edit in a **chips token-field** (committed tags are removable chips, the input only holds the tag being typed — no separators; per-token accent-insensitive type-ahead over tag ids + glosses, Enter/Tab picks, space/comma/paste commits, ⌫ on empty pops the last chip), then apply to any of three targets — the Obsidian note frontmatter, the PDF's macOS **Finder tags**, and the parent **Zotero item** (via Zotero's local HTTP API, never SQLite). Every write is confirm-gated, controlled-vocabulary-validated server-side, `log_vault_write`-audited, and reversible from an in-panel **Restore** over the `tagging/journal.py` manifest. Needs a completed audit scan (reuses its results). **Two views** (toggle persisted in `localStorage.tagging_view`, default `deck`): the original **Table** (all papers side-by-side; overview/bulk) and a keyboard-first **Triage deck** — one card at a time, untagged-first, showing a PDF-text excerpt (`/api/tagging/snippet` — cache-first; a fresh extract is genuinely bounded to the first 3 pages with the whole-file MarkItDown fallback disabled, and a no-text document writes a `<sha>.notext` negative-cache marker so later cards fast-fail instead of re-scanning; the module-scoped client cache survives re-renders and the next card's snippet is prefetched sequentially); `P` propose · `A`/Enter accept (→ **all three targets at once** in one confirm via `/api/tagging/apply-all`, degrading gracefully when a target is absent/off-platform/unreachable, each still journalled as its own reversible op; **optimistic** — the deck advances immediately after the confirm and the outcome, failures included, reconciles into the deck-level `#tagging-deck-lastresult` status line that survives the card change) · `S`/→ skip · `M` defer to a review queue · `V` toggle an on-demand **full-PDF side panel** (blob-URL fetched with the header — never an `/api` iframe src — closed + blob revoked on card change; `open-pdf` macOS fallback) · ⌫ undo (confirm-gated like Accept — it rewrites user data via `/restore`; peek-not-pop, so a fully-failed undo stays retryable; **busy-gated** — the undo stack fills post-response, so a ⌫ during an in-flight apply-all would revert the wrong accept) · `1`–`9` toggle the current card's proposed chips (cleared on every card render — a leftover list would inject the previous paper's tags). **Every** Propose/Apply outcome is shown in a visible status line (previously only a screen-reader announcement, so a sighted user saw nothing). **2026-07-19 batch:** the `confirmInline` strip is keyboard-operable everywhere (it stops Enter/Space propagation so native button activation runs, and handles Escape — pre-fix the deck's verb handler made the confirm mouse-only) and the deck ignores keys from inside a strip or on a focused button; each new card is announced to the SR status region (title + year); vocab + the Zotero probe load in parallel behind a staged loading line, an inventory failure gets a Retry error boundary, and `window.taggingTeardown` (called by audit.js when another report takes the panel) revokes the PDF blob URL + removes the `tagging-active` overflow opt-out (which un-clips the type-ahead dropdown; tagging's tables carry their own scroll wrapper). See Module Ownership (`tagging/`, `api/routes/tagging.py`) and the `/api/tagging/*` routes.
- Deck Generator. Turn a topic + free-form instructions into a LaTeX **Beamer** deck grounded in the indexed vault, in the user's own template's house style. Pick (and edit in-app) a Beamer template; deckgen reuses its preamble + custom macros (`\citefoot`, `\commonlogo`), maps cites to the template's `_master.bib` when possible, and scaffolds a compile-ready `<slug>/<slug>.tex` + `Makefile` into the suite. **Emit-only by default** — the user compiles with `make`; the exceptions are (a) the opt-in, confirm-gated **Compile & Auto-Fix** loop (`/api/deck/compile-fix`): our own bounded `latexmk -no-shell-escape` run + LLM log-repair passes, every written repair screened and verified by a follow-up compile, `.bak` before the first write; and (b) the **Preview PDF** action (`/api/deck/compile-preview` + `preview-pdf`): one plain latexmk pass that never touches the `.tex` (build artifacts only) and renders the PDF in-app. Details in `deckgen/README.md`.
- Report / Article Generator (`docgen/`). The prose sibling of the Deck Generator: turn a topic + free-form instructions into a LaTeX **article/report** (`\documentclass{article}`, prose sections — not slides) grounded in the indexed vault, in the user's own template's house style, OR a long-form **Markdown note written into the vault**. Built on `deckgen`'s engine: `deckgen/latex.py` is the extracted document-class-agnostic substrate (metadata/title/dangerous-macro/cite/graphics/comment/template-assembly + `validate_common` + the `DocClassStrategy` seam); `deckgen/assemble.py` binds `BEAMER`, `docgen/article.py` binds `ARTICLE` (prose `sanitize_article_section` — a `\section` gate, not a frame gate). `deckgen/sections.py`/`outline.py` are parametrized with document-class hooks (sanitize / prompts / placeholder, defaulting to Beamer so the deck path is byte-identical) that `docgen/generate.py` (LaTeX) and `docgen/markdown.py` (Markdown) bind. **LaTeX is emit-only** (`/api/docgen/generate` scaffolds `<slug>/<slug>.tex` + `Makefile`, like the deck; shared route helpers in `api/routes/_latexdoc.py`). **Markdown writes ONE new note into the vault** (`/api/docgen/generate-md`), reversibly via the third vault-write path (see *Vault-write auditing*). Config knobs `docgen_*` mirror `deck_*` (with a Settings-window "Report / Article · generation" section). **Augment** (deepen/table/new-section/reformat an existing article), **Preview PDF**, and **Compile & Auto-Fix** are implemented too — full parity with the deck's emit-only exceptions, using `docgen/review.py::screen_article_repair` (the article safety gate: structural floor is "≥1 `\section`", not "≥1 frame").
- Plain Chat. A RAG-free, multi-turn conversation with the globally-configured provider/model — no vault retrieval, no agent loop, no tools. Stateless server: the browser owns the `{role,content}` history and sends the last 20 turns on every send; conversation is ephemeral (lost on reload). Two persisted knobs (`chat_temperature`/`chat_system_prompt`); the system prompt is the **full** system prompt (no retrieval grounding to protect). Streams through the unified `core.llm.chat.stream_chat_messages` for both local and online providers, falling back only before the first token. Both chat panels (plain + vault) offer **Export MD/TXT** of the client-side transcript to `~/Downloads` via `/api/export-summary` (the vault panel keeps its own `_vaultHistory` array for this — the server still holds no history), and the main free-text inputs (deck topic/title/instructions/audience, plain-chat input, focus question) persist their last value across app quits via `ui.js::installDraftPersistence` (localStorage; restore fills only an empty field).

## Module Ownership

- `app.py` creates the Flask application and registers blueprints. It also exposes `FEEDBACK_FILE` and `CONFIG_FILE` as module-level attributes so the reset test can patch them via `mock.patch('app.FEEDBACK_FILE', ...)`.
- `core/driver.py` + `cli/main.py` + `mcp_server/server.py` are the **headless CLI + MCP surface** (the `papermind` command + a stdio JSON-RPC MCP server for local AI agents). **HTTP-first, by design** (rewritten 2026-07-21; repaired end-to-end 2026-07-22 Batch C after the audit found the generate tools had never worked): `core/driver.py` is a thin client over the app's own `/api/*` endpoints, always sending the `X-Requested-With: ChatEKLD` header the origin guard requires, so it reuses the app's real validation/confirm-gating/journalling/single-writer-locking instead of a second drift-prone reimplementation. **Server discovery (2026-07-22):** the running server (GUI or headless) writes `BASE_DIR/server.json` (`core/server_info.py` — pid-gated cleanup, atomic write) once its socket is probe-verified; `driver.resolve_base_url()` resolves at CALL time: `CHATEKLD_API_URL` (authoritative — no fallback when dead) → the server-info file (pid alive + `/api/health` probe) → the legacy `:5000` probe. `papermind server` REFUSES to start beside a live server (two processes would hold two independent op-locks over one vault) and binds loopback only — the old `--unsafe-bind` was removed as provably dead (the origin guard fail-closes on non-loopback clients). **Install story:** no `[project]` table (deliberate) — `python -m cli` works from the checkout, and `scripts/install_cli.py` writes a marker-gated `~/.local/bin/papermind` shim; the CLI/MCP surface is NOT in the frozen `.app`. **Writes require the running server**; only read-only status/config have an in-process fallback (`get_status` returns ONE canonical shape on both paths, `vault_index` from `get_status_payload()`). Deck/docgen generation loads the template via `/api/*/load-template` server-side, then posts `template_tex`+`out_dir` (CLI `--template` required; MCP `template_path`). Over MCP the write tools call the **same confirm-gated endpoints the GUI uses** (`confirm:true`); `_is_write_call` classifies writes (incl. markdown `generate_document`, which writes a vault note) for the BOUNDED single-slot semaphore (300 s → `-32000` busy) + `log_vault_write`. The JSON-RPC layer guarantees a response for every id (guarded `process_line`/params gates/`resources/read`; unknown tool → `-32602`; client `protocolVersion` echoed). Driver write calls carry op-sized timeouts (apply 900 s) and a "write MAY have landed" note on client-side network failures. **Ratchet v2:** the driver's declarative `ENDPOINTS` registry is checked for path AND method + literal-completeness (`tests/test_driver_contracts.py`), and `tests/test_driver_replay.py` replays every driver-built request against the real routes (SSE workers stubbed) so request-BODY drift fails the suite — the harness that would have caught the dead generate tools. `scripts/install_mcp.py` registers the server with Claude Code (via `claude mcp add`) **and with Cursor** (2026-08-08 — a conservative merge into `~/.cursor/mcp.json`: other servers/keys preserved, a stale `papermind` entry refreshed, an unparseable file never overwritten — the snippet is printed for manual merge instead; pinned by `tests/test_mcp_server.py::TestInstallMcpCursorRegistration`), and prints an OpenClaw config snippet (it does not register there), warning when the interpreter can't import the app deps.
- `api/routes/` owns route handlers.
- `api/security.py` owns local-origin request checks and `sanitise_error_msg`.
- `api/validators.py` owns request-body coercion helpers (`coerce_int_in_range`, `coerce_float_in_range`, `coerce_bool`, `coerce_enum`, `coerce_regex`, `coerce_non_empty_string`, `coerce_string_max_len`, `first_valid`, `MISSING`). Every route layer imports from here rather than reimplementing NaN/Inf/range/clamp logic — `api/routes/vault.py::_resolve_chat_params` is the canonical caller.
- `api/sse.py` owns the shared backend SSE skeleton (item 4.3): `run_sse_worker(worker, *, consumer_timeout_s, preflight_msgs, release)` — bounded queue + daemon worker + stall guard + `data:`-framed drain + `Cache-Control: no-cache`/`X-Accel-Buffering: no` — and `_SSEOpGuard` (the promoted `_DeckOpGuard`: *release* fires exactly once, when the stream has ended — generator finally OR `call_on_close` — AND any spawned worker exited; pinned by `test_deck.py::TestDeckOpGuard`). Every SSE route runs through it (vault chat, plain chat, paper summarise, refactor, deck, docgen, tagging — 15 call sites across 7 route modules). `sanitise_error_msg` is imported from `api.security` (its owner) — the first Batch 2 cut imported it from `core.utils` and broke app boot.
- `core/paths.py` owns `resolve_under_root(raw, root, *, must_exist, must_be_dir, must_be_file, exts, deny_root, max_len)` (item 4.2) — the traversal/NUL/escape-rejecting validator for path inputs that resolve **under a known root**; returns the canonical posix rel or `None`. It is the single chokepoint behind **all** of `refactor.py`'s route validators, and behind `deck.py`'s figure-copy + `audit.py`'s scan-pdf/reveal-root resolution. Path inputs that are user-chosen **absolute** locations with no under-root anchor — `deck.py`'s `_resolve_template_path`/`_resolve_out_dir`/`_resolve_existing_deck` and `audit.py`'s `_normalise_rel_path`/`_normalise_abs_path` — cannot use it (it needs a root and returns a rel) and each apply their own inline NUL/newline + `realpath` + `_DENY_PREFIXES` guards, so a future hardening of `resolve_under_root` must be mirrored into those hand-rolled validators. Scope-locked wrappers (e.g. `refactor.py::_resolve_scope_note_rel`) resolve against the VAULT root and prefix-check the scope rel — resolving against the scope dir instead doubles the scope segment (the repaired first-cut bug, pinned by `test_scope_note_rel_validator_rejects_escapes`).

The `chat_temperature`/`chat_system_prompt` knobs are persisted by `settings.js` (LLM Settings modal), not by `plainchat.js`.
- `static/js/` owns UI behaviour. `refactor.js` follows the same `ui.js`+`api.js`-only import rule (wired into `app.js` as `window.refactorRunPlan`; tab `#tab-refactor`/`#refactor-tab`). `updateProviderBadge` lives in `ui.js` so `config.js` and `app.js` can both import it without a circular dependency. `audit.js`, `deck.js`, and `settings.js` follow the same `ui.js`+`api.js`-only import rule. `audit.js` also owns the **cross-report search** UI (`#audit-search-bar` / `#audit-search-results`, wired once from `initAuditTab`): a debounced query against `/api/audit/search` behind its own `makeLatestGate`, rendered as an **overlay over** `#audit-report-body` rather than a mode — closing it restores exactly the report the user was on, meta line included. **The typed query and the overlay are separate lifetimes** (`_hideSearchResults` vs `_clearSearch`): closing the overlay — a sub-`MIN_QUERY_LEN` keystroke, or any tab switch, since `selectAuditReport` calls `_hideSearchResults` — **keeps the text**, and only the explicit Clear button / Escape empties it. Routing the short-query path through the clearing variant was a real defect: pausing mid-word past the 220 ms debounce erased the letter just typed, and every jump-to-report cost a retype. While a query is typed but closed, `#audit-search-restore` ("Show results") and Enter both re-open it without a retype. The search bar shares the tablist's post-scan visibility through `_setTabsVisible`. The wire-once guard is a **dataset marker on the input element**, not a module flag: a module-scoped boolean stays true after the node is replaced and would silently leave the new input unwired (caught by `tests/js/auditSearch.test.js`). `settings.js` owns the **LLM Settings** modal (`#settings-modal`): the previously-UI-less plumbing keys (including the vision/OCR bounds `vision_timeout_s`/`vision_max_tokens`/`ocr_max_tokens`), the config-only `vault_*` knobs it already owned (`vault_reranker_model`/`vault_reranker_device`/`vault_vector_backend`/`vault_prewarm_enabled`) **and now the vault-thesaurus config-only group** (`vault_thesaurus_abbrev_path`/`vault_thesaurus_tags_path`/`vault_thesaurus_max_variants`/`vault_primer_max_chars`/`vault_primer_header`/`vault_primer_core_terms` — `set-thesaurus-*` / `set-primer-*` controls), plus the `paper_*`/`deck_*`/`chat_*` persistence (the Plain Chat `chat_temperature` slider + `chat_system_prompt` textarea). The vault chat **live-override** knobs (incl. the `vault-thesaurus-enabled` / `vault-primer-enabled` toggles), OCR/Vision provider/model selects, and provider/model selectors physically live inside the same modal but are still operated **by element id** by their original owners (`vault.js`, `config.js`) — the markup was relocated, not the logic — so `settings.js` deliberately does not touch them (no double-save).

## Provider Rules

- `provider` selects `ollama`, `lm_studio`, `openai`, `anthropic`, `google`, `deepseek`, `zai`, or `openrouter`.
- Online providers (`openai`, `anthropic`, `google`, `deepseek`, `zai`, `openrouter`) are CHAT-ONLY — they never expose an embedding interface. When the active chat provider is online, the indexer, vault chat, and prewarm resolve a local embed provider via `core.config.resolve_embed_provider(cfg, provider_name)` (falls back to `embed_provider`, default `ollama`). DeepSeek, Z.AI (Zhipu GLM) and OpenRouter are OpenAI-compatible endpoints served by `core/llm/adapters/openai_compat.py` — thin `_OpenAICompatProvider` subclasses overriding `name` / key-env / base-url / curated list (plus, for OpenRouter, `_is_capability_routing_error` — the 503/404 strip-tools heal); adding another compat provider means one subclass plus the registration points (`ONLINE_PROVIDER_NAMES` in factory + config, `_ONLINE_MODEL_KEYS`/`_ONLINE_DEFAULT_MODELS`, `api/routes/config.py::_PROVIDER_NAMES` + a `*_model` row in `_CONFIG_VALIDATORS`, a `DEFAULT_*_MODEL` constant + `_DEFAULTS` key, `PRICING_TABLE` rows + the `unpriced_curated_models` loop, two `<option>`s in `templates/index.html`, `config.js::_ONLINE_MODEL_KEYS`, and **`static/js/ui.js`'s `isOnlineProvider` `_ONLINE_PROVIDERS` set + `_PROVIDER_LABELS`** — missing these makes the client treat the provider as LOCAL and disable the embed selector, the C4/2026-07-13 bug from the 2026-07-12 provider axis). Both halves of that checklist are now ratcheted (2026-08-08): `test_llm.py::test_online_provider_registries_agree` pins the server-side registries against each other and `tests/js/providerRegistry.test.js` pins the HTML optgroup ↔ `config.js` ↔ `ui.js` parity, so a missed point fails the suite instead of shipping the C4 bug again. **OpenRouter specifics:** namespaced model ids (`vendor/model`, price-bearing `:free`/`:batch` variant suffixes — see the namespaced-id guard in `usage.estimate_cost_usd`), curated set verified tools-capable against its public `GET /api/v1/models` 2026-08-08, attribution headers deliberately not sent, and its internal upstream routing composes with (does not replace) the app's `fallback_provider` policy.
- `core.providers.get_provider(name)` always returns a local `Provider`; called with an online name it silently substitutes the configured local embed provider. `core.llm.get_llm_provider(name)` returns the unified `LLMProvider` chat interface for both local and online.
- API keys come from env vars (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY`, `DEEPSEEK_API_KEY`, `ZAI_API_KEY`/`ZHIPU_API_KEY`, `OPENROUTER_API_KEY`, and the non-LLM `ZOTERO_API_KEY` used by the tagging web transport) at call time — never persisted to `config.json`, never returned by `/api/config`. `<PROVIDER>_BASE_URL` env vars override the compat adapters' built-in endpoints. `api.security.sanitise_error_msg` runs through `core.llm.redact.redact` so an accidental key leak in an exception is stripped before the UI sees it.
- Per-provider model selections persist independently: `llm` for local providers, `openai_model` / `anthropic_model` / `google_model` / `deepseek_model` / `zai_model` / `openrouter_model` for online; `core.config.resolve_chat_model(cfg, provider_name)` picks the right field. `/api/config` routes the UI's generic `llm` field into the active online provider's key and then **drops** `llm` from the payload — persisting an online model name into `llm` would clobber the local selection (pinned by `smoke_test.py::test_03b`).
- `/api/models` routes to the active provider. For online providers it returns `CURATED_MODELS` merged with a best-effort, key-gated, short-TTL-cached live fetch from the provider's models endpoint (`core.llm.model_listing`); curated stays first and degrades to curated-only without a key / offline / on error. `/api/status` ok=True for online providers just means the API key is set. `/api/pull` is Ollama-only (chunks serialised via `.model_dump()`).
- Fallback policy: `fallback_provider` + `fallback_on` config keys; falls back only on transient errors and only **before the first streamed token**; hard quota/billing errors are terminal. Full mechanics in `core/llm/CLAUDE.md`.
- Token / USD-cost usage is recorded by `core.llm.usage.usage_tracker` for every request and surfaced on `/api/usage`; pricing in `PRICING_TABLE`, overridable via `llm_pricing_overrides`. Details in `core/llm/CLAUDE.md`.
- OCR and vision settings are separate from chat provider settings. `/api/vision-models?provider=...` lists models for Ollama or LM Studio only; `ocr_provider` / `vision_provider` decide which backend receives image calls.

## Vault Rules

- The indexer reads `.md` and `.pdf` files. `.docx` is excluded by design. PDFs are folder-driven (every `.pdf` in an included folder is eligible). Images are note-driven: only files whose extension appears in `vault_image_exts` AND that are referenced from an included markdown note are described by the vision model and embedded; `[]` disables image indexing; skipped images are counted in `skipped_image_count`.
- `obsidian_vault_path` is validated before save — broad roots and system directories are rejected. `vault_exclude_dirs` stores vault-relative paths; exclusions are applied before files are read. **Vault-switch semantics (A1, 2026-07-13):** `POST /api/config` calls `obsidian_manager.cleanup()` + `reset_prewarm()` whenever the normalized `obsidian_vault_path` actually changes — dropping the in-memory index and every retrieval cache (BM25/wikilink/thesaurus sidecars, prewarm state) so the next chat can't answer from the previous vault's loaded index (the on-disk index dir is left intact; only `/api/reset` deletes). `obsidian_meta.json` records `vault_path`; the incremental gate refuses a reindex whose recorded vault differs (forces a fresh rebuild + `.bak` archive), so a switch can't fuse two vaults' chunks. A missing `vault_path` (pre-fix index) is grandfathered — adopted for the current vault, not rebuilt. **`embed_provider` (2026-07-27)** records which LOCAL backend produced the vectors (`ollama` vs `lm_studio`), stamped by `_write_index_meta` at both the checkpoint and final-persist sites. A gate right after the `vault_path` one **REFUSES the run** (error state, returns before touching anything) when a *recorded* provider differs from the current one — it deliberately does NOT rebuild. The same model name served by Ollama vs LM Studio can be a differently quantized/pooled build whose vectors are not comparable, but `resolve_embed_provider` returns the *chat* provider unchanged when it is local, so the resolved backend is a function of the **chat-model dropdown**: a silent rebuild would turn `ollama ↔ lm_studio` (or `lm_studio →` any online provider, which falls back to the untouched `embed_provider` default) into an unconfirmed multi-hour re-embed triggered by a setting that looks unrelated. The refusal quotes the chunk count and offers both exits (switch back, or rebuild); `index_vault(..., force_fresh=True)` is the explicit opt-in, **exposed end-to-end since 2026-07-29**: `POST /api/obsidian/index` accepts a `force_fresh` body field (strict `coerce_bool`), sent only by the confirm-gated "Rebuild from scratch" action the vault error boundary offers on an `embed_backend_mismatch`. The refusal itself reaches the user through the **persistent `error_code`/`error_detail` status-payload fields** (2026-07-29 audit 0.1): the drained `messages` channel was destroyed in the same poll tick the client's error branch blanked the status line, so the recovery instructions never survived to the screen — `vault.js::_showVaultIndexError` renders the detail and keys its actions on the code (a refusal offers Rebuild, never a Retry that re-fails identically). Grandfathering keeps the evidence (`_prev_embed_provider`): recorded `embed_provider` → else the recorded `provider` **when local** (it predates the new field and, when local, is by definition what `resolve_embed_provider` would have returned) → else adopt silently and stamp. So no existing index is forced to reindex on upgrade, but the first post-upgrade run of a genuinely-switched backend refuses instead of silently mixing vector spaces. Identity-driven archives (vault switch, `force_fresh`) are marked protected and pruned in their own window (`_INDEX_BAK_PROTECTED_KEEP = 5`) so routine version-bump churn (`keep=2`) can never evict them. Details in `rag/CLAUDE.md`.
- Index updates are incremental: unchanged chunks are skipped by document hash, changed chunks are replaced, stale chunks are deleted. Indexing streams end-to-end (peak RAM bounded by the largest single document); checkpoints persist after 500 inserts *and* ≥ 10 minutes since the previous one (each checkpoint rewrites the whole store); per-insert failures are tolerated up to 20 consecutive. **The stale sweep is the run's LAST phase and is batched on lancedb** (`_STALE_DELETE_BATCH` = 500, 2026-07-16): a per-chunk `delete_ref_doc` is one full table scan + version manifest each (~3 s), so a reorganised attachments folder (measured: 436k stale = 52% of a live index) projected to ~15 days and never finished — and since the sweep runs last, each abandoned attempt re-stranded the whole backlog, compounding until the docstore held 2× the vault. It is also cancel-aware per batch (it previously checked `_stop_event` only *before* the loop, so Cancel was inert and killing the process was the only exit — the source of the "possible torn write" drift) and emits progress (the old loop emitted nothing for its whole duration and read as a hang). Details in `rag/CLAUDE.md`.
- **Vector store backend** (`vault_vector_backend`, `simple` | `lancedb`, default `simple`). `simple` is the legacy JSON `SimpleVectorStore`; `lancedb` is the binary Apache-Arrow backend (low resident RAM, fast cold start, transactional inserts — no full-store JSON dump for *vectors*, though the docstore/index-store JSON still persist at the checkpoint cadence). The knob governs only **fresh** builds; an existing index's backend is authoritative from `obsidian_meta.json` (`vector_backend`; missing ⇒ `simple`). Migrate an existing vault in place with **no re-embedding** via `python scripts/migrate_vector_store.py` (app closed), or set the knob and reindex. On lancedb the embeddings are unit-normalized so default-L2 ranking equals cosine; list metadata (`attachments`) is JSON-stringified in the row while the docstore keeps the list (`store_nodes_override=True`). Each streaming insert is its own LanceDB transaction (a version manifest that re-lists every fragment, so an unbounded run grows `_versions/` ~O(n²)); the indexer compacts + prunes superseded versions (`Table.optimize`) at each checkpoint **and** every `_LANCEDB_COMPACT_EVERY` (2000) inserts, keeping the on-disk footprint O(n). `scripts/compact_lancedb.py` is a one-off offline reclaim for an index bloated before this existed. Mechanics in `rag/CLAUDE.md`.
- Chunking is **pinned** (changing it forces a reindex; `TestReindexInvariant` guards it): `.md` at heading boundaries (`MarkdownNodeParser`), then a **conditional secondary cap pass** that sub-splits only sections over `MD_MAX_CHUNK_TOKENS` (1024, `core/constants.py` — a pinned constant, not a config knob, since it changes chunk IDs) so a long single-heading section is no longer silently truncated by the embedding model's ~2048-token limit; PDF flat-text via `SentenceSplitter` (512-token chunks, 64-token overlap). Chunk IDs are `"{rel_path}::{sha1(f"{i}\n{text}")[:16]}"`; page-range documents from large PDFs (> 1000 pages, one document per 1000-page range) salt the hash input with their `page_start` (the input becomes `f"{page_start}:{i}\n{text}"`) so ranges of the same file cannot collide — single-document files keep the unsalted input, so they never re-embed. The secondary pass is churn-free for under-cap sections (it keeps the original node object, so `i`+text and the doc_id are byte-identical); only notes containing an oversized section re-chunk that section onward. Details in `rag/CLAUDE.md`.
- Vault RAG prompts treat retrieved notes/PDFs as untrusted source text, apply a similarity cutoff, and construct per-query LLM/embedding objects instead of mutating global LlamaIndex settings.
- Vault chat accepts query-time knobs as per-request overrides on `/api/obsidian/chat`, resolved by `_resolve_chat_params` (body wins, then the persisted `vault_*` config key, then the engine default) — **all reindex-free**:
  - Generation: `top_k` (1-32, default 8), `similarity_cutoff` (0.0-1.0, default 0.25), `prompt_mode` (`strict`/`balanced`/`exploratory`/`concise`), `temperature` (0.0-2.0, default 0.3), `system_prompt` (≤ `SYSTEM_PROMPT_LIMIT` = 4000 chars; a prefix over the mode template — the safety preamble stays app-controlled).
  - Retrieval: `hybrid_enabled`, `reranker_enabled` (both default `True`; **config-only, not body overrides:** `vault_rrf_dense_weight` / `vault_rrf_bm25_weight` (0.0–10.0, default 1.0) weight the fusion legs — at the 1.0 defaults fusion stays `reciprocal_rerank` byte-identically, any other value switches that query to `relative_score`, the only LlamaIndex mode that applies `retriever_weights`; score scales differ between modes, so tune against `tests/eval/` — see `rag/CLAUDE.md`), `mmr_enabled` + `mmr_lambda` (default off / 0.5), `query_expansion` + `num_queries` (default off / 3, local providers only), `rerank_pool_ceiling` (10-200, default 50), `wikilink_expansion` (default off; the only wikilink knob that is a body override).
  - Vault thesaurus (curated glossary files; default paths `_abreviations.md` / `_tags.md` at the vault root): `thesaurus_expansion` (default off; body override) drives deterministic synonym query expansion via `_ThesaurusExpansionRetriever`; `primer_enabled` (default off; body override) injects a small app-controlled glossary block into the system prompt so the LLM can read the vault's shorthand. **Config-only** (not body overrides): the file paths `vault_thesaurus_abbrev_path` / `vault_thesaurus_tags_path` (vault-relative, "" disables the slot), the depth knobs `vault_thesaurus_max_variants` (1-8, default 3) and `vault_primer_max_chars` (500-8000, default 1500), and the content overrides `vault_primer_header` / `vault_primer_core_terms` ("" ⇒ built-in defaults). Both features no-op when neither configured file exists. See the **Vault thesaurus** bullet below and `rag/CLAUDE.md`.
- **Wikilink graph expansion** (`vault_wikilink_expansion`, default `False`; body field `wikilink_expansion`). Query-time, **reindex-free**: after retrieval, the result set is widened with chunks from notes the seeds link to **and** notes that link into them (outbound ∪ backlinks), fetched from the docstore, *before* the rerank stage decides what survives (rerank-gated — irrelevant neighbours drop out, final answer size unchanged). **Only takes effect when the reranker is active** (the default): the reranker (`top_n = top_k`) is what trims seeds+neighbours back to `top_k`, so with the reranker off the engine skips the wrap (and `stream_chat`/`retrieve` skip the graph build) rather than push >`top_k` chunks at the model. The note→note graph is built lazily from the docstore (regex over `.md` node text + Obsidian shortest-path resolution against indexed sources) and cached like BM25 — invalidated by `_invalidate_retrieval_caches`, optionally warmed by `prewarm`, and persisted to an on-disk sidecar (`obsidian_storage/wikilink_sidecar.json`, BM25-sidecar discipline; mechanics in `rag/CLAUDE.md`) so a process-cold chat loads it instead of re-sweeping the docstore; `_get_wikilink_index`/`_WikilinkGraph` in `rag/sidecars.py` (re-exported from `rag/vault.py`), `_WikilinkExpansionRetriever` (one wrap in `_build_retrieval_pipeline`, before the postprocessors) in `rag/engine.py`. Caps are **config-only** (`vault_wikilink_neighbor_cap` 1-100/10, `vault_wikilink_node_cap` 1-200/24, `vault_wikilink_score_decay` 0.0-1.0/0.5; the engine reads them from `cfg` like the rerank-pool knobs). Applies to single-shot RAG (and the agent's RAG fallback) only — **not** the agent's active `vault_search`, matching `mmr_enabled`/`query_expansion`. The UI toggle (`#vault-wikilink-enabled`) is owned by `vault.js` like the other live retrieval knobs.
- **Vault thesaurus** (`vault_thesaurus_expansion` + `vault_primer_enabled`, both default `False`; body fields `thesaurus_expansion` / `primer_enabled`). Query-time, **reindex-free** and **embed-free**. The thesaurus is parsed from two hand-curated Markdown tables whose **vault-relative paths are configurable** — `vault_thesaurus_abbrev_path` (default `_abreviations.md`) and `vault_thesaurus_tags_path` (default `_tags.md`); an empty value disables that slot. `_get_thesaurus()` resolves each under the vault root (`_resolve_thesaurus_rel` rejects traversal/absolute/escaping, defence-in-depth over the `/api/config` shape check), reads + parses them lazily (cached by the resolved paths **plus** each file's `(size, mtime_ns)` signature, so an edit to a file *or* a config path change refreshes on the next chat; cleared on vault switch / `cleanup()`), and returns `None` — disabling both features — when neither resolved file exists. The app-independent parser/consumers live in `rag/thesaurus.py` (stdlib-only, like `rag/lancedb_store.py`): (1) **query expansion** (`expand_query`) substitutes a matched concept/abbreviation with each known synonym, one rewritten query variant per synonym (config-capped at `vault_thesaurus_max_variants`), each retrieved separately and rank-fused via `_ThesaurusExpansionRetriever` in `rag/engine.py` — so the dense leg is not diluted and BM25 can hit the synonym token; (2) **system-prompt primer** (`build_primer`) renders a compact glossary block (≤ `vault_primer_max_chars`, query-relevant rows first) prepended to the answer-mode template via `_apply_vault_primer`, so the LLM can *read* shorthand that survives into the retrieved context. Both apply to single-shot RAG (and the agent's RAG fallback) only — **not** the agent's active `vault_search`, matching `wikilink_expansion`/`mmr_enabled`/`query_expansion`. **Domain defaults (overridable):** `rag/thesaurus.py`'s built-ins are tuned for the maintainer's bilingual French/English psychiatry/clinical-research vault, but the corpus-specific pieces are now config-driven — `vault_primer_header` replaces the `_PRIMER_HEADER` intro sentence and `vault_primer_core_terms` (comma-separated) replaces the `_CORE_PRIMER_TERMS` priority list (both empty ⇒ built-ins), and the parser accepts **English** column headers (`Abbreviation | Meaning`, `Description | Tag`) as well as French. The `≠` collision convention stays a documented marker. Defaults-off so it is invisible to vaults that don't opt in. Covered by `test_thesaurus.py`.
- Reranker model is set via the `vault_reranker_model` config key (editable in the **LLM Settings** window, or `POST /api/config` directly — both local-only) but is **never** a `/api/obsidian/chat` body override (prevents a malicious page from triggering arbitrary HuggingFace downloads). `launch.py` enables `HF_HUB_OFFLINE=1` at startup when the model is already cached. `vault_reranker_device` (`auto`/`cpu`/`mps`, default `auto`, also Settings-window/`/api/config`-set, not a body override) selects the cross-encoder's device: `auto` keeps the library's own inference (MPS on Apple Silicon when available), `cpu` is the escape hatch that keeps unified memory free for the LLM, and any non-CPU failure degrades to CPU for the session instead of disabling reranking.
- `vault_prewarm_enabled` (default `True`) gates the launch-time prewarm inside `ObsidianVaultManager.prewarm()`: when off, prewarm reports `skipped` (terminal for the UI — Send stays enabled) and the first chat lazy-loads instead. Defers the multi-GB load; does not remove it.
- Retrieval mechanics (RRF fusion, MMR, rerank pool sizing, cutoff semantics, BM25/reranker caches, the persisted BM25 sidecar under `obsidian_storage/bm25_index/`, prewarm, lock discipline) are documented in `rag/CLAUDE.md`.

## Agent Mode (Vault Chat)

- Opt-in alternative to single-shot RAG on `/api/obsidian/chat`: `#vault-agent-enabled` checkbox (`vault_agent_enabled`, default `False`) or body field `agent_enabled`. When off, `stream_chat` runs byte-for-byte identically — the agent layer is entirely additive.
- Three tools over `ObsidianVaultManager`: `vault_search(query, top_k≤12)` (results carry `is_image` from the chunk metadata the indexer stamps on vision-described images — the deck runner's figure prompt keys on it), `vault_read_note(rel_path)`, `vault_list_materials(filter?, limit≤200)`. Tool output is truncated and wrapped in the untrusted-content guard (per-call nonce'd tag — content containing a literal closing tag can't escape the wrapper).
- **Optional fourth tool `web_search` (2026-07-22, Batch C — `core/agent/web_tools.py`).** Tavily-backed, client-side (NOT the providers' native server-side search — Anthropic `web_search`, Gemini grounding, OpenAI Responses — those bypass `wrap_untrusted` and need per-adapter wire work; that native-tool path is the recorded **v2**, take it up only deliberately). Triple gate (`web_search_available`): `vault_web_search_enabled` on (default off; Settings/vault-panel checkbox `#vault-websearch-enabled`, body override `web_search_enabled` — the route passes its resolved value as `enabled_override`, 2026-07-23, so a body `true` works before the debounced Settings save lands) AND the active chat provider is **online** (maintainer decision: local models excluded for now) AND `TAVILY_API_KEY` in the env at call time (never persisted/returned; `tvly-` shape in `core/llm/redact.py`). Registered in `api/routes/vault.py::_run_agent` (knob-on-but-unavailable emits an explanatory `{"info"}`) and `deckgen/inprocess.py` (config-only). Runner: stdlib urllib POST via a **no-redirect opener** (2026-07-23 — the default handler carries the Authorization header to the Location target, and permits https→http, so a 3xx from a compromised endpoint could exfiltrate the key), Bearer header (key never in the body), response body **read-capped at 2 MB before JSON parsing**, timeout clipped to the turn's remaining wall-clock (refuses under 5 s), results snipped to 1200 chars ×`vault_web_search_max_results` (1–8, default 5); HTTP errors surface status-only (never the attacker-influenced body). Results flow through the same nonce'd untrusted wrapper as vault content — web pages are the canonical injection vector. This is the app's one deliberate egress exception beyond LLM providers + Zotero (README documents it).
- **Tool names must match `^[A-Za-z_][A-Za-z0-9_-]{0,63}$`** — `ToolRegistry` raises `ValueError` at construction otherwise. This is the strictest intersection of the providers' rules; the pre-2026-07-02 dotted names (`vault.search`) were 400'd by OpenAI *and* Anthropic on every tool-enabled request (the mocked test suite can't see provider-side validation — `test_llm.py::TestProviderToolPayloadContract` is the in-process stand-in).
- Loop budget `vault_agent_max_iterations` (default 6, clamped 1–12); 300 s wall-clock cap. Two consecutive malformed tool-call iterations fall back to plain RAG against the original message; a session-level capability warning fires after two consecutive fallback turns.
- Full loop/fallback/wire-format details in `core/agent/CLAUDE.md` and `core/llm/CLAUDE.md`.

## Single Paper Rules

- Prompt presets are structured dictionaries in `core/constants.py`.
- Built-in report types are merged with saved custom/overridden report types by `core.config.load_report_types()`.
- `/api/summarise` accepts `temperature`, `num_ctx`, `max_tokens`, `top_p`, `repeat_penalty`, `focus_question`, `audience`, `language`, `report_type_id`, and optional `system_prompt`. Slower, never silent — a residual over-budget reduce input is clipped WITH an info notice. Pinned by `TestProviderRegressions::test_{lm_studio,ollama}_summary_over_budget_runs_map_reduce`, the four `test_map_reduce_*` bound/cancel/heartbeat tests, and `test_local_summary_within_budget_is_not_truncated`.

## Library Audit Rules

- **Manual-only.** No code path outside `POST /api/audit/scan` may call `audit_manager.start_scan()`; `create_app()` must leave the audit `idle` (pinned by `test_audit.py::TestFlaskAppBootDoesNotScan`).
- **Read-only, with ONE explicit write exception.** External stores (Zotero SQLite via `mode=ro` snapshot, PDFs via pikepdf, BibTeX, Finder xattrs) are never mutated, and the *scan* writes no vault content — it does maintain two `BASE_DIR/audit/` sidecars: the regenerable `hash_cache.json` (the duplicate scan's `(size,mtime)→sha256` memo) and a re-anchoring pass over `mapping.json`'s `hashes` map (`bridge.refresh_mapping_hashes`, scan-time only — moved there from the per-POST path by the 2026-07-21 audit). The audit's writable surfaces are exactly three — two decision sidecars under `BASE_DIR/audit/` plus the one vault write: (a) `BASE_DIR/audit/mapping.json` (manual PDF↔bib curation — now also carrying a per-entry content-hash `hashes` map so a curated PDF that is renamed/moved is re-linked by sha256 at the next scan, source `manual_hash`; the scan-time re-anchor narrows the old annotate-then-move gap to files modified *and* moved between two scans — still a documented limitation; four writers touch it: the verbs `add_match`, `add_no_match`, and `clear_curation` — the last being the triage deck's undo, a new *verb* on the same file and lock, not a new write surface — plus the scan-time `refresh_mapping_hashes`); (b) `BASE_DIR/audit/dup_decisions.json` (2026-08-05 — the near-duplicate report's persisted "not a duplicate" pair-ids, written by `POST /api/audit/dup-decision` with `dismiss`/`clear` verbs, `clear` being the undo checked first, mapping-route precedent); and (c) `POST /api/audit/apply-tag-drift`, the audit's only vault-mutating action — it writes missing Zotero tags into one Obsidian note's frontmatter, confirm-gated, tags server-validated against the record's actual drift set (fingerprint-keyed since 2026-08-05 via `audit/engine/normalize.py::tag_key`, the same comparison the report uses — a tag the note carries under another spelling is a report *variant*, informational and never applyable), under the obsidian op-lock, with a non-clobbering `<note>.md.bak` (first backup = true original) + `log_vault_write("audit_tag_add", …)`; the edit touches ONLY the `tags:` frontmatter field via `api/routes/_audit_tagwrite.py` (YAML-quoting + a post-merge round-trip guard that refuses rather than corrupt). The **Finder Tag Drift fix buttons (2026-08-06) are NOT a fourth surface**: they dispatch client-side to the *tagging* subsystem's journalled writers (`/api/tagging/apply-note-tags` / `apply-finder-tags` / `add-vocab-tag` — see the tagging section), so the audit's own write inventory is unchanged and the vendored `audit/` tree still writes nothing; the report payload's `vocab_ids` field (built by `api/routes/audit.py::_vocab_id_resolver` — vocabulary ids indexed by `canonical_tag_key` with the SAME `_drift_synonyms` map as the drift comparison) is what bridges the audit's fingerprint identity to the writers' literal-id vocab gate, so an applied row actually closes at the next scan.
- The audit reuses `obsidian_vault_path`; all other subpaths are validated config keys, and the generic `POST /api/config` strips `audit_*` keys so the validators cannot be bypassed.
- Lifecycle, result cache, Finder-tag/`reveal` platform limits, and frontmatter-warning surfacing are documented in `audit/CLAUDE.md`.

## OCR / Vision Availability Caching

The configured OCR/Vision model is always the model that gets called. `check_availability()` is informational only (cached 60 s); it never gates a call and never rewrites `self.model`. A negative-result cooldown fast-fails calls after a failure so per-page traffic cannot hammer a missing model — the window is the `vision_failure_cooldown_s` config key (0–600, default 30; **0 disables** — every image retries immediately), read per call via `services.vision._failure_cooldown_s` (its own reader, NOT `_cfg_bounded_int`, whose `≤0 ⇒ default` contract would erase the disable). During indexing, images inside the window are silently skipped, so a shorter window trades retry traffic against fewer dropped images after a transient blip. `set_model()` / `set_provider()` invalidate both caches immediately.

**Call bounds (always on).** Every `VisionManager.describe_image` / `GLMOCRManager.extract_page_text` call is bounded so a runaway or stuck local model cannot stall a multi-hour indexing run — the OpenAI/LM Studio SDK default is otherwise a 600 s timeout × 2 retries (= 30 min per stuck image). The transports (`_chat_lm_studio_image`, `_chat_ollama_image`) take keyword-only `timeout`/`max_tokens`: LM Studio goes through the shared cached `core.providers.lms.get_lmstudio_client(host, timeout)` (which forces `max_retries=0`, matching `VISION_MAX_RETRIES`) and passes `max_tokens` to `create(...)`; Ollama uses the timed `_ollama_client(resolve_ollama_host(), timeout)` and `options={"num_predict": max_tokens}`. The timeout/cap come from `vision_timeout_s` (5-600, default 120; **always on — no "0 = off"** unlike `local_request_timeout_s`), `vision_max_tokens` (default 1536), and `ocr_max_tokens` (default 4096), read **per call** via `_cfg_bounded_int` (lazy `load_config`, like `local_request_timeout()`) so a Settings change applies without restart; a missing/≤0/garbage value falls back to the hard `DEFAULT_*` constant and a positive out-of-range value is clamped to the validator's range (re-asserting the bound for a hand-edited `config.json`). The **description path** (not OCR — that would hurt text legibility) additionally pre-emptively downscales images whose longest side exceeds `VISION_IMAGE_MAX_SIDE` (1568 px) via `_fit_base64_image_to_max_side`, a best-effort PNG re-encode that returns the original on any failure (undecodable image — a format PIL can't open, or a corrupt file; note HEIC **is** decodable here, since `pillow-heif` is a pinned dependency and `services/vision.py` calls `register_heif_opener()` at import — or non-image input). Downscale is invisible to the description cache (`rag/vault.py` keys it on the *original* image bytes); the OCR in-memory cache likewise keys on the *original* `base64_png`, not the overflow-downscaled payload. `_chat_lm_studio_image` never forwards `timeout=None` (the SDK can read that as "no timeout").

## JS Module Hierarchy

`api.js` is the leaf module — it imports nothing from this project. `ui.js` imports only `api.js` (for `logError` / `secureFetch`). All other modules (`config.js`, `vault.js`, `summarizer.js`, `audit.js`, `deck.js`, `docgen.js`, `help.js`, `settings.js`, `plainchat.js`, `prompts.js`, `refactor.js`, `tagging.js`) import only from `ui.js` and `api.js`, with the documented exceptions that `vault.js` and `summarizer.js` also import from `config.js` (to read active settings and model choices without causing circular dependencies). `app.js` is the root and imports from all others. This prevents circular dependencies; in particular `config.js` must never import from `app.js`.

`ui.js::renderExampleChips(targetEl, examples, {mountEl?, title?, lang?})` is the shared click-to-insert "example prompt" primitive: it renders a row of chips that, on click, **fill an empty field but append (after a blank line) to a non-empty one** so a user's draft is never clobbered, then dispatch an `input` event (so debounced-save / `oninput` listeners react as if typed), pure-DOM via `textContent` (never innerHTML), idempotent per field. The French, vault-tuned example sets live at the call sites — `app.js::wireExamplePrompts()` for the three static fields (deck instructions, vault-chat system prompt, plain-chat input) and `refactor.js` for the per-note free-prompt textarea (created at render time, so it can't be wired statically).

**Help & discoverability (Batch H, 2026-07-22).** `help.js` owns three surfaces: the `HELP_ENTRIES` "?"-badge table (now covering the vault-chat retrieval/agent knobs, web-search toggle, and Plain Chat), the **Help tab** (`loadHelpTab()` — lazily fetches `static/help/guide.md` on tab activation and renders it through vendored `marked`+`sanitiseHtml` with a plain-text fallback; retry-on-failure), and the **guided tour** (`startTour()` over `TOUR_STEPS`, launched only from the Help tab's "Show me around" button — never auto-fired). The tour and the **⌘K command palette** are dependency-free primitives in `ui.js` (`runTour(steps)`, `installCommandPalette(actions)` — driver.js was considered and skipped to keep the vendor surface at zero); `app.js::_paletteActions()` owns the action registry (navigation + safe actions only — writes keep their own confirmed buttons; ui.js stays feature-blind per the hierarchy). Pinned by `tests/js/commandPalette.test.js`. **Single help source (2026-08-05):** `guide.md` is the app's only full guide — the old sidebar `#howto-modal` (a second, independently-authored guide that had drifted from it) was merged in and deleted; the sidebar "How to Use" button routes to the Help tab via `window.openHowTo` (showTab + `loadHelpTab`, since the loader is lazy). Never hardcode the audit report-tab count in help copy (the 9-vs-11 drift class). Pinned by `tests/js/helpButton.test.js`.

`ui.js::confirmInline(anchorEl, {message, confirmLabel, onConfirm})` is the shared destructive-action ceremony (Track 6e): a one-shot inline confirm strip, Cancel first in DOM/focus order, replace-not-stack. **Every button that overwrites a user file or bulk-reverts vault state must route through it** — the deck apply-repair/apply-augment handlers and refactor's Revert-all do, pinned by `tests/js/confirmCeremony.test.js` (including a source ratchet on deck.js). Streamed generation announces its lifecycle through `ui.js::announceStatus` → the static `#sr-status-announcer` region (Track 6b; `tests/js/liveRegions.test.js` pins which status elements are static live regions — add `role="status"` in `index.html`, not at write time, for anything AT must hear). Theme color tokens are contrast-linted: `tests/js/contrastTokens.test.js` recomputes WCAG ratios from `styles.css` per theme (Track 6a) — when adding a token or reusing one on a new surface, add the (fg, bg, min) pair there; `--accent-hover` is text-grade and `--accent-hover-bg` is the hover surface (one value cannot be both).

Third-party JS is vendored under `static/js/vendor/` — currently `marked.min.js` (v15.0.12, MIT). Never load runtime JS from a CDN: the PyWebView renderer's network is independent of the Python process, and a failed CDN fetch used to surface as `ReferenceError: Can't find variable: marked`, destroying the chat answer at render time. `vault.js::_renderAnswer` falls back to plain text when `marked` is unavailable. User-controlled strings (folder names, paths) must never be interpolated into `innerHTML` — use `createElement`/`textContent` (see `renderExclusions`) or an escape helper (see `audit.js::_esc`).

## SSE Contract

Streaming routes emit JSON events, one per `data:` frame, ending with `data: [DONE]`:

```text
data: {"token": "..."}     # answer tokens
data: {"error": "..."}     # structured error (also mid-stream, before [DONE])
data: {"info": "..."}      # stage labels, fallback notices, agent usage footer
```

Error frames may carry additive machine-identity fields alongside the message — currently `code: "size_cap"` on the deck/docgen augment over-cap refusal (2026-07-23; `api.js::consumeSSE` passes the whole frame as `onError`'s second argument so clients key offers on `code`, never on regexing the prose).

Single-shot `/api/obsidian/chat` additionally emits one `{"retrieval": [{source, score, is_image}, …]}` frame after retrieval and before the token stream (rendered as the collapsed "Retrieval Context" panel in `vault.js`); the deck routes' terminal frames are `{"deck": …}` / `{"augment": …}` / `{"compile": …}` as documented under API Routes.

**Provenance frames (2026-07-22).** The three chat/summary streams (`/api/plainchat`, `/api/summarise`, `/api/obsidian/chat`) emit one `{"meta": {provider, model, …}}` frame **before** the first token (plainchat adds `temperature`; summarise adds the five resolved generation knobs; vault adds `agent_enabled`) and, best-effort after a clean stream, one `{"usage": {input_tokens, output_tokens, cost_usd, requests | iteration_count}}` frame — agent turns compute it from the loop's `UsageBudget`, the other paths from `usage_tracker.records_since(start_iso, …)` (ring-only; `core/llm/usage.py::usage_frame_payload`). The clients store both on the assistant turn (`_history` / `_vaultHistory` / `_lastSummaryMeta`) and `ui.js::buildConversationExport` renders them (plus per-turn `{source, score}` retrieval objects and the agent `tool_call` trace) into the MD/TXT exports; the generators stamp their outputs directly (`api/routes/_latexdoc.py::provenance_comment` prepended to deck/article `.tex` before validate/review, and `docgen/markdown.py::assemble_markdown(frontmatter=…)` YAML on vault notes). Both frames are additive — a client that ignores them sees the legacy stream.

Agent-mode `/api/obsidian/chat` adds four event types before the final token stream:

```text
data: {"iteration": N}
data: {"thought": "..."}
data: {"tool_call": {"id": "...", "name": "...", "arguments": {...}}}
data: {"tool_result": {"tool_call_id": "...", "content": "...", "is_error": false, "truncated": false}}
```

## Limits

- PDF upload limit: 500 MB. PDF extraction timeout: 600 seconds. PDF page ceiling: `PDF_MAX_PAGES` = 20 000 (shared by the upload worker and the vault indexer; both extract in 1000-page ranges, so the ceiling bounds time, not memory).
- System prompt limit: `SYSTEM_PROMPT_LIMIT` = 4000 characters (shared by single-paper and vault-chat `system_prompt`; defined in `core/constants.py`).
- Feedback field cap: 10 000 characters per string field.
- Obsidian operation lock TTL: **per-acquisition, set by the caller** — indexing / tagging / docgen acquire with 3600 s; the Note Refactor write routes acquire with `_WRITE_LOCK_TTL_S = 600` and heartbeat to extend. (The single "3600 s" figure here previously implied one global TTL; it is a per-`try_acquire_lock(ttl=…)` value.) A holder that lets the TTL lapse while still working has its next `heartbeat()` return `False`; long holders must act on that (the indexer's `_heartbeat_or_stop` aborts the run — see *Logging* discipline), never discard it.
- **Timeout chain** (nested; outer must exceed inner or the inner cap is defeated): `local_request_timeout_s` (per local HTTP call) ≤ `agent_wall_clock_s` (one agent turn / each deck section, the exact user cap) ≤ SSE consumer `event_q.get(timeout=max(cap, online_aware_floor_s) + SSE_STALL_MARGIN_S)` ≤ frontend fetch abort. **`online_timeout_s` is IN the chain since 2026-07-22** (`api/sse.py::online_aware_floor_s` widens the single-shot floor to it on the vault/plain-chat/paper routes — previously a 500 s online knob was killed by the fixed 330 s consumer guard mid-legal-call). The SSE worker additionally abandons a HALF-OPEN consumer whose queue stays continuously full past `consumer_timeout + 60 s` (audit P6). The cap is config-driven (`agent_wall_clock_s`, default 300, parsed defensively with `coerce_int_in_range` so a hand-edited config can't crash the route). The consumer stall guard and the vault.js abort **derive** from it, but both are **floored at `SSE_SINGLE_SHOT_FLOOR_S = 300`** (`SSE_STALL_MARGIN_S = 30`; vault.js abort = `(max(cap,300)+60)*1000`) — both constants now live in `core/constants.py`, shared by the vault, deck, and plain-chat SSE routes (plain chat has no agent cap, so its consumer wait is just `SSE_SINGLE_SHOT_FLOOR_S + SSE_STALL_MARGIN_S`): the agent path is bounded by its own deadline, but the *same* consumer loop also serves the single-shot RAG path whose only time guard is the consumer — so lowering the cap to bound agent turns must not starve a slow single-shot first token. The vault.js abort is computed **live at send time** in `_chatAbortMs()` (reads the `set-agent-wall-clock` control), NOT cached at init, so a change in the Settings modal takes effect on the next Send without reload. `deck.py` passes the cap to `InProcessChatRunner(turn_timeout_s=...)`. The `_CHAT_TOKEN_TIMEOUT_S = 300` constants are now just the default fallback.
- **Local request timeout** (`local_request_timeout_s`, default 0 = leave each path's SDK default): threaded through `core.providers.base.local_request_timeout()` into `OllamaProvider._client()` (ollama streaming + the agent tool path in `local.py`; the client is cached per `(host, timeout)` in `core/providers/ollama.py` so generation reuses one httpx pool — `get_provider()` returns a fresh provider each call) and `get_llm` (LlamaIndex Ollama `request_timeout`, whose own default is 30 s), plus the LM Studio paths. The LM Studio streaming + agent-tool clients go through `core.providers.lms.get_lmstudio_client`, which **caches** the `openai.OpenAI` client per `(base_url, timeout)` (mirroring the Ollama cache — a fresh per-call client leaked an httpx pool), forces **`max_retries=0`** (the SDK otherwise retries a timed-out call up to 2 more times *internally*, each up to the full per-call `timeout`, so one wedged call could block ~3×timeout and blow past the SSE consumer's stall window — the deck-generation random-failure mode; with retries off, one call is bounded by exactly one `timeout` and recovery is owned at the app level: the deckgen per-section retry, the agent loop's deadline), and rounds/floors the timeout to whole seconds (a non-positive value leaves the SDK default, never `0` = time-out-immediately); the agent path's per-call timeout is **quantised to a coarse ceiling ladder** (`core/agent/loop.py::_TIMEOUT_BUCKETS`, item 2.6) so the caches see at most ~8 keys per host instead of one per remaining-second — a wedged call may outlive the deadline by at most the gap to its bucket (one such call max; the loop's deadline gates bound the rest). Both client caches are themselves **bounded LRUs** (`_CLIENT_CACHE_MAX` = 8; evicted clients are not closed in place — a concurrent call may still stream on them — the dropped reference lets GC close them; pinned by `TestClientCacheBound`). Read per call so the knob applies without restart. **Scope: chat/generation only** — embeddings are excluded from *this* knob (bounding indexing batches would cause spurious failures rather than recovery); the **query-path** embed instead has its own independent always-on bound (item 2.1): `Provider.get_embedding(..., request_timeout_s=…)` with `QUERY_EMBED_TIMEOUT_S` = 30 s (`rag/engine.py`) bounds the single retrieval-time embed HTTP call because it runs while holding `_index_mutation_lock`, and the chat path acquires that lock via a 120 s timed `_acquire_retrieval_lock` (clean error, not an indefinite hang — details in `rag/CLAUDE.md` §Lock discipline); indexing embeds (constructed *without* `request_timeout_s`) stay deliberately unbounded. **Vision/OCR is also excluded**: it has its own always-on bound (`vision_timeout_s`, default 120) so indexing-time image/OCR calls are capped independently of this chat knob (see *OCR / Vision Availability Caching → Call bounds*).

## Security Notes

- Local API calls require `X-Requested-With: ChatEKLD`.
- External `Origin` / `Referer` hosts are rejected; with neither header present (normal for PyWebView), the request is accepted only from a loopback `remote_addr`.
- The `Host` header is allowlisted to `127.0.0.1` / `localhost` / `::1` (`api/security.py`) — the DNS-rebinding defence that holds even when every other check passes.
- Stored app data lives in an owner-only app data directory.
- Error messages are sanitised (and API-key-redacted) before they reach the UI.
- Rendered-markdown HTML (vault chat, plain chat, refactor previews) passes through the single `ui.js::sanitiseHtml` gate. Its scheme test normalises each attribute value the way the HTML URL parser does — strip tab/LF/CR anywhere, trim C0 controls + space at the ends, entity decoding already done by DOMParser — **before** matching `javascript:`/`vbscript:`/`data:text/html`, so control-character placement (`jav&#9;ascript:`) cannot smuggle a blocked scheme. Pinned by `tests/js/sanitiseHtml.test.js`.
- Streaming routes emit structured JSON error events before `[DONE]` when generation fails mid-stream.

## Build & Distribution

`install_and_build.sh` (macOS-only) is the single build entry point. Cross-cutting invariants:

- **arm64-only.** The PyInstaller invocation passes `--target-arch arm64`, and the script hard-fails on a non-arm64 build host (`HOST_ARCH="$(uname -m)"` guard, right after the Darwin check). Intel is **unsupported as a target**: the native wheels (torch/lancedb/pyarrow/tokenizers) are not reliably cross-buildable to universal2 or x86_64 from an arm64 host, and Rosetta only translates Intel→Apple-Silicon (never the reverse), so an x86_64 artifact would fail on Apple Silicon just as an arm64 one fails on Intel. `--target-arch arm64` also *asserts* every collected binary has an arm64 slice — a foreign-arch dependency now fails the build loudly instead of shipping a broken bundle.
- **Ad-hoc signed, never notarized.** `codesign --force --sign -` only (no Developer ID, no `--options runtime`, no entitlements — the hardened-runtime keys are inert without `--options runtime`, which requires a Developer ID + notarization we deliberately don't do). A locally built bundle launches on the build machine (no `com.apple.quarantine`); a **transferred** copy is Gatekeeper-blocked until the recipient runs `xattr -dr com.apple.quarantine <app>` (documented in the README and inside the `.dmg`).
- **`.dmg` is the delivery wrapper.** The build emits both `ChatEKLD_<date>.app` (run in place) and `ChatEKLD_<date>.dmg` (share). The image stages the `.app` + an `/Applications` drag-target symlink + a generated `READ ME FIRST.txt` (dated app/binary names + the un-quarantine step) + `packaging/seed_models.command` when that file exists (the offline model-seed helper — see below). Both dated artifacts are git-ignored (`ChatEKLD_*.app/`, `ChatEKLD_*.dmg`).
- **Model caches live OUTSIDE the bundle and are seeded per-machine.** tiktoken BPE (`TIKTOKEN_CACHE_DIR`), NLTK punkt/stopwords (`NLTK_DATA_DIR`), and the ~67 MB HF cross-encoder (`~/.cache/huggingface`) are downloaded by `install_and_build.sh` into the **build machine's** dirs — a copy-only `.app` on a fresh Mac has none of them, so its first *offline* index fails (the LlamaIndex `SentenceSplitter` needs tiktoken + NLTK) and its first chat downloads the reranker. The chosen distribution model is a per-machine seed: the DMG's `packaging/seed_models.command` finds the installed app and runs its frozen binary with `--seed-models`. That flag is handled by `launch.py::seed_models()` at module top level **before** the heavy `import webview; from app import app` block (a `sys.argv` membership test, so Finder's legacy `-psn_…` arg can't match it), so seeding needs neither the native webview framework nor the Flask app — it lazily imports the SAME bundled tiktoken/nltk/sentence-transformers the app uses, downloads all three into the exact locations the app reads, then `raise SystemExit(rc)` (rc≠0 if any download failed, so the `.command` can tell the user to re-run online). Requires network once; afterward the app indexes and chats fully offline. Bundling the caches into the `.app` was deliberately rejected (would bloat the read-only bundle + need a copy-on-first-run redirect). Pinned by `test_launch.py` (seed fetches all three, returns non-zero on failure, and the argv branch exits without starting the window).
- **Desktop widgets ship in the DMG, not the `.app`.** `packaging/widgets/` holds the two optional companions over `BASE_DIR/widget.json` (see the `widget/` Module Ownership bullet): `chatekld.1d.py` (SwiftBar/xbar menu-bar plugin — stdlib-only python3, file-first with a live `GET /api/widget` preference when `server.json` names a live pid; hard rule in its docstring: never the draining status endpoints) and `chatekld-widget.jsx` (Übersicht desktop card — display-only, `cat`s the file, zero API calls), plus their install `README.md`. The build stages the folder into the DMG (`widgets/`, `seed_models.command` precedent) and the generated READ-ME points at it; users install by hand into SwiftBar's plugin folder / Übersicht's widgets folder. The `.py` plugin rides the `py_compile` sweeps (`packaging/widgets/*.py`); the `.jsx` has no gate (noted — Übersicht parses it, our CI does not).
- **The local model runner is external, not bundled.** The app shells out to a system Ollama / LM Studio (`core/providers/server.py`, resolved against a Homebrew-augmented PATH for the Finder-minimal env). A fresh Mac must install a runner + pull an embed/chat model, or set an online key in `BASE_DIR/.env` (`.env.example` is the template the README points at). First-run guidance surfaces the missing-runner / no-model state through the existing `#runtime-warning` banner (see the `/api/health` A4 note above) — no new UI. (A5, an in-app "set API key" affordance that writes `BASE_DIR/.env`, is deferred — the `.env.example` + README path is the current route.)
